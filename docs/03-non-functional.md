# 4. 非機能・設計上の考慮点

- **ローカル利用を基本**: リクエスト定義・環境設定・履歴などは原則としてユーザーの PC 内に保存する。
- **セキュリティ**: トークンや API キーを不用意にログ出力しない。秘密情報の保存方法・暗号化・OS の資格情報管理機能の利用。
- **通信データの秘匿**: 観測したリクエスト／レスポンスには Cookie・トークン・個人情報が含まれ得る。保存・表示・エクスポート時にマスキングできる設計にする。
- **安定性**: タイムアウト・接続失敗・不正な JSON・巨大なレスポンス・キャンセルを適切に扱う。
- **操作性**: リクエスト編集・レスポンス確認・履歴／通信一覧を行き来しやすい UI にする。
- **保守性**: UI・HTTP 通信・永続化・テスト実行・プロキシを適切に分離する。
- **拡張性**: 将来の通信観測・CLI 実行・CI 連携を追加しやすい構造を目指す。
- **対応 OS**: まず macOS（開発 PC）で作って動かす。Windows は全機能の完成後に動作確認する段階として追加する。
- **具体的な数値**: 履歴は最新 1,000 件まで、10MB を超える本文は先頭のみ表示、通信は 1 秒以内に一覧へ反映、プロキシは自分の PC からのみ利用可能。詳しくは [要件定義](04-requirements.md#非機能要件) の N1〜N6。
